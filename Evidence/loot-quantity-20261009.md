# 当前版本的粒子掉落数量

## 证据版本与边界

本次只读分析针对 Steam 当前安装的 GameAssembly.dll：

- SHA256：`375f3a8db0e5dff69b78a74e0518b98d83214eb7e5bcdc428386615ddbcbc04f`。
- PE ImageBase：`0x180000000`。下文地址均为当前 DLL 的 RVA。
- 方法地址由当前 IL2CPP v39 元数据和当前 PE 的 CodeGenModule 方法指针映射取得，不沿用旧 DLL 的地址。
- 网站计算成果的资源快照仍绑定 `e603dc61c6561762d81934c28e694af1d06ec1f7206074310cfce20cecf35993`；本次没有变更计算器输入或计算成果。

使用 UnityPy 读取当前资源，与旧快照的原始 JSON 树逐项比较：GameData 的 CommitId、lootIotaTables、lootTraitTables，以及 EncounterDetails 的 CommitId、全部 encounterDetails 完全一致；RecipeSpecificationDetails 的 CommitId、全部 sparseRecipes 也完全一致。31 个自由回想中，30 个 BaseRolls 为 4，回想 85 为 0。资源 CommitId 均为 `007d2f885f0fd931ce7621030ff08311fb74f13b`。

此证据说明当前版本的数量路径。它不证明两个 DLL 的所有游戏规则都相同，也不把静态分析冒充游戏实测。

## 基础抽取次数和每组颗数

`ResultsScene.Start` 当前入口为 RVA `0x7358C0`。普通掉落分支在 `0x7380C2–0x738152` 检查音乐成绩不低于 80,000,000、非失败及相关通关标志；在 `0x73819F–0x7381BE` 检查通常掉落路径和非空粒子池。下述公式适用于该分支已经允许掉落的情况。

`0x7381E0–0x7381F1` 从回想对象偏移 `0x18` 读取 BaseRolls。`0x73849D` 把最终次数传给 `_c._C`（RVA `0x47E090`）；后者每轮选择一个粒子配置。BaseRolls 的单位是抽取次数，不能直接称为总颗数。

每轮随后经过 `_c._d`（调用位置 `0x7385C0`）确定精度和技能，再由 `0x738618–0x73865A` 生成该组的 Count：

```text
Count = ceil(Random.Range(float.Epsilon, 5 + IotaStackBoost))
```

- `0x7384A5` 读取的单精度下界常量位于 RVA `0x260C690`，原始位模式为 `0x00000001`，即 float.Epsilon。
- `0x738618` 读取 GlobalSkillLevels 偏移 4，即 IotaStackBoost；随后加 5 作为随机上界。
- `0x73862D` 调用浮点 Random.Range，`0x738651` 调用向上取整函数。其当前实现 `0x3D98E0–0x3D9989` 对正的非整数向上取整。
- `0x73865A` 写入粒子实例偏移 12；IotaInstance 的该字段为 ushort Count。

因此，按通常的均匀随机数学口径，技能等级 L 时每组为 1 至 `5+L` 颗，平均 `(6+L)/2` 颗。无堆叠技能时平均 3 颗；满级 5 时平均 5.5 颗。原生浮点随机数及随机取整最终产生整数数量，单次结果会有波动。

## 全局技能的最大等级

`_K._zh._GnA`（RVA `0x4B61B0`）遍历所有配方及各挑战奖励，按奖励类型累加技能；`_gnA`（`0x4B69C0`）另结合存档解锁情况取得玩家现有等级。最大等级来自全部可获得的奖励之和，不是假设一个统一上限。

当前 switch 表位于 RVA `0x4B65F4`。RewardType 11 分支 `0x4B64E4` 累加 GlobalSkillLevels 偏移 3，RewardType 12 分支 `0x4B650E` 累加偏移 4。按当前 sparseRecipes 奖励汇总：

| 字段 | RewardType | 满级 | 配方 ID 与挑战索引（从 0 开始） |
| --- | --- | --- | --- |
| IotaRetrievalBoost | 11 | 3 | 3/2、9/2、34/1，各加 1 |
| IotaStackBoost | 12 | 5 | 2/2、13/2、16/1、33/1、67/2，各加 1 |

其他全局字段的奖励总和为：DiscoveryBoost 1、IntuitionBoost 4、CardInventoryExpansion 5、IotaPotencyBoost 5、IotaPotencyMaximization 2。数量路径直接读取 Retrieval 和 Stack；精度相关技能在 `_c._d` 中影响粒子精度，不增加 Count。

## 星级奖励与谱面时间倍率

`0x737DF4–0x737E5D` 调用 BattleScore.get_TotalBattleScore、GetStarResult 和 `_wG._KlA`，把星瓣总数除以 5，得到战斗星级 S。它不是歌曲音乐分数，也不是只数完整星标的整数。

GetStarResult（`0x482B20–0x482D45`）返回五个字节，分别保存五个星标的已亮花瓣数，每项为 0 至 5；`0x482CF7` 在最高分支把后四项全写为 5。未满星标的分支在 `0x482D00–0x482D3E` 写入花瓣余数并清零后面的星标。`_wG._KlA`（`0x49E230–0x49E23F`）把这五项相加；`0x737E5D` 再除以单精度常量 5。因此 S 按 0.2 递增，最高 5。五项为 `[5,5,5,5,1]` 时总花瓣 21，对应 S=4.2；全部为 5 时对应 S=5。

在 `0x738242–0x7382AC`，星级额外次数为：

```text
R_star = randomRound(max(S - 1, 0))
```

这里 randomRound 对非整数的整数部分保留，以小数部分为概率再加 1；使用该随机取整的数学期望就是输入值。`0x73826E` 求整数部分，`0x738280` 在 0 至 1 之间抽浮点随机数，`0x73828F–0x7382A2` 取余数、比较后决定补 1。S=4.2 时，星级奖励 3.2 次通常约 80% 取 3、20% 取 4；S=5 时为 4 次。原生单精度与随机端点有有限精度差异，百分比按通常数学口径说明。

时间倍率的来源是 `GameScene` 的协程 `_vB.MoveNext`：

1. `0x718367` 调用 LogicalNotePlayer._Vb（RVA `0x52AF30`）。
2. `_Vb` 在 `0x52AF91–0x52AFB4` 取最后一个 `_cH` 的偏移 16。
3. `_cH..ctor`（`0x4B5590`）的第三个参数名为 absoluteTimestampMs，写到结构偏移 16；它是绝对判定时间，不是成绩。
4. `0x71836C–0x71838A` 使用 RVA `0x260A0E0` 的 double 常量 0.001，计算 `Tms * 0.001 + 0.001`，存入 ResultsScene 静态字段偏移 `0xF8`。
5. `0x7382D9–0x73830C` 读取该值，除以 double 100.0（RVA `0x260A4E8`），并与 1.0 取较大值。

因此，倍率 M 的通常数学表达式为：

```text
M = max(1, (Tms + 1) / 100000)
```

Tms 指末个判定的绝对时间。它与音频总时长、选曲界面的展示时长未必完全相同，使用歌曲时必须从实际谱面取得相应值。

在 `0x738318–0x738398`，原生先以 float 计算 `(M-1) * (B + R_star + R_retrieval)`，再随机取整为时间额外次数；`0x73839E–0x7383A4` 累加四项后传给 `_c._C`。这里的 R_star 已经经过上一步取整。最终次数是 `B + R_retrieval + R_star + R_time`，不是把未取整的星级项和时间项合并后只取整一次；两种做法的单次数量分布不同。

## 条件期望与实际使用条件

忽略浮点随机端点的有限精度效应，按原生随机取整对应的通常数学期望：

```text
E[抽取次数 | S,T] = (B + IotaRetrievalBoost + max(S - 1, 0)) * M
E[总颗数 | S,T] = E[抽取次数 | S,T] * (6 + IotaStackBoost) / 2

满数量技能时：
E[总颗数 | S,T] = (B + 3 + max(S - 1, 0)) * max(1, (Tms + 1)/100000) * 5.5
```

歌曲 PD 可以满足成绩条件，但不能单独指定战斗星级和末键时间。不同配队、谱面等级和判定数可能改变战斗结果；不同歌曲会改变时间倍率。仅凭“满全局技能 + PD”不能为每个回想写一个唯一的平均颗数。计算某组具体期望数时，必须给出 S、T 或明确示例条件，不能默认为某首歌或五星。

满数量技能、M=1、S=5 时，B=4 的回想为 11 组、平均 60.5 颗；B=0 的回想为 7 组、平均 38.5 颗。满数量技能、M=1、S=4.2、B=4 时，约 80% 抽 10 组、20% 抽 11 组，平均 10.2 组、56.1 颗。这些是固定条件示例，不是各歌曲统一的掉落数量。

回想 85 虽然 B=0，粒子池仍非空；普通路径的数量公式没有因为 B=0 而排除全局技能和星级奖励。只有次数技能为 0 且星级奖励为 0 时，组数才为 0，时间倍率不会把 0 组变成正数。不能把基础次数 0 解释成总数量必为 0。

## 配置排除轮换与展示概率

`_c._C` 每轮经 IotaDropTableState._sPA（`0x4B80A0–0x4B815F`）收集未排除的配置、累加它们的权重，再按权重选择。选中后调用 `_SPA`（`0x4B7F90–0x4B808D`）：在排除位集中标记该配置，检查当前粒子颜色的全部配置；如果该颜色都已标记，就清除此颜色的标记。其他颜色不一起重置。

网页的粒子百分比为配置权重除完整池总权重，表示没有排除时的基础比例；当前下一组概率要使用未排除的配置及其总权重。因此连续多组不能称为固定概率的独立抽样，基础比例乘组数也不是精确的长期配置期望。相同技能池合并展示不合并原始抽取配置，技能百分比仍按绑定池的每次抽取权重解释。

`_c._d` 在 `0x47E594–0x47E6C5` 最多按该配置 TraitRolls 次抽取绑定技能池；每次使用池总权重，不动态删除已抽的权重。无效／空结果跳过，已选配置项不重复加入，技能数在 `0x47E6B5–0x47E6B8` 达到 3 后提前停止。因此 TraitRolls 是最多尝试次数，百分比是单次权重比例，不是整组最终技能组合概率。

以上证据仅用于说明基础次数、每组数量和概率口径，不改变计算算法或成果。
